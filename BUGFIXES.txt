                    metheorMultiV2 - Minimal Surgical Bug Fixes
================================================================================

Target: metheorMultiV2 (directly faithful to metheorMulti)

1. DESIGN PRINCIPLE
--------------------------------------------------------------------------------
Follow the original architecture and dataflow of metheorMulti strictly.
Avoid any artificial over-engineering (no custom streaming sliding windows,
no complex chunk batching channels). Keep modifications minimal, clear, and
focused strictly on fixing the two true bugs in upstream metheor.


2. THE TWO TRUE BUGS & SURGICAL FIXES
--------------------------------------------------------------------------------

[Fix 1] Strand & Coordinate Determination (src/readutil.rs)
- Original Bug:
  `if (r.flags() == 0) || (r.flags() == 99) || (r.flags() == 147)`
  used strict integer equality. Reads carrying composite flags (e.g. duplicate
  bit 0x400 -> Flag 1123, or supplementary/secondary bits) failed the check and
  wrongly fell into the reverse-strand branch ((abspos - 1)), shifting genomic
  coordinates by 1bp and destroying CpG concordance. In addition, Bismark's
  explicit conversion tag `XG` was ignored.
- Minimal Fix:
  1. If Bismark `XG` tag is present: "CT" -> OT (top strand), "GA" -> OB (bottom strand).
  2. Fallback: Bitwise flag queries `(!r.is_reverse() && r.is_first_in_template()) || (r.is_reverse() && r.is_last_in_template())`
     for paired-end, or `!r.is_reverse()` for single-end.


[Fix 2] CIGAR Soft-Clip & Extended Match Handling (src/tag.rs)
- Original Bug:
  When parsing CIGAR, `Cigar::SoftClip` was caught by `_ => {}`, leaving
  `used_read_len` unadvanced. This caused:
  1. The read sequence to align out-of-phase against the reference genome.
  2. The generated `XM` string to be shorter than the actual read.
  Also, CIGAR `=` (`Cigar::Equal`) and `X` (`Cigar::Diff`) were unhandled.
- Minimal Fix:
  1. Recognize `Cigar::Equal` and `Cigar::Diff` alongside `Cigar::Match`.
  2. Separate leading and trailing soft clips from the aligned portion:
     - The aligned read slice `read_seq[leading..len - trailing]` is aligned
       against the undisturbed genomic reference sequence, fully preserving
       natural CpG dinucleotide context at boundaries.
     - Soft-clipped bases are prepended and appended as '.' in the final XM string,
       ensuring XM length matches read length exactly.


3. ME ENTROPY CALCULATION (src/me.rs)
--------------------------------------------------------------------------------
- Retained the exact original `metheorMulti` accumulation logic:
  Accumulates 4-CpG patterns into `HashMap<readutil::Quartet, QuartetStat>`
  (single-threaded `compute_helper` for `-t 1`, multi-threaded `compute_helper_mt`
  for `-t > 1`).
- Preserved the full 22-column TSV format (chrom, pos1..4, me, c0..c15).
- Added a simple 3-line coordinate sort (`sort_by_key`) right before writing output,
  ensuring output rows are strictly and deterministically ordered by genomic coordinate.

5. V3 REFERENCE-CONTEXT FIX (2026-09-14)
--------------------------------------------------------------------------------
The V2 sections above describe earlier changes. V3 now assigns XM context from
consecutive genomic reference bases instead of constructing context across read
deletions or insertions. For example, CAGT aligned to C-GT remains CHG (X/x),
not CpG (Z/z). Existing strand selection and reference-coordinate conventions
are retained. Inserted/soft-clipped bases receive dots; deletions/reference skips
advance only the reference cursor. XM retains one character per read base.

Files:
- src/tag.rs: replace gap-dependent context reconstruction with CIGAR position
  mapping and direct reference-context lookup; shared by both tagging paths.
- src/tag_context_tests.rs: expected tags for indels, both strands and mate
  orientations, clipping, extended CIGAR operations, ambiguous bases and genome
  boundaries; CpG coordinate checks; false-quartet regression; a small real
  BAM -> tag -> me regression with expected positions, counts and entropy.

6. V3 STRAND AND INPUT-RECORD CORRECTNESS (2026-09-14)
--------------------------------------------------------------------------------
- XM generation and CpG coordinate extraction now share is_top_strand().
  XG:Z:CT/GA takes precedence; without XG, use each record's flags under the
  existing directional-library assumption. The first BAM record no longer
  determines paired-end handling for every record. Reject invalid XG values.
- tag assigns dots to unmapped records and replaces existing XM tags when
  explicitly re-tagging. me excludes unmapped records in both counting paths.
- Reject non-ASCII or length-mismatched XM strings instead of silently
  truncating CpG extraction through zip().
- The four-CpG entropy formula, read-level counting (including overlapping
  mates), MAPQ threshold, merged-count depth threshold, and 22 columns are
  unchanged. CpG context remains based on the reference genome.

Independent tests were added to src/tag_context_tests.rs:
- All 16 patterns with explicit XM, coordinate and pattern-index expectations;
  single/paired reads, both strands, extra flag bits, XG overrides.
- Malformed XM/XG rejection, re-tagging, unmapped and mixed-pairing input.
- BAM -> tag -> me with fixed expected counts and entropies 0, 0.25, 0.5,
  0.2028195311147832 (3:1 mixture), and 1 (uniform over 16 patterns).
  The uniform case has 8208 reads, crossing the 8192-record batch boundary.
  Both single-thread and multi-thread outputs are checked against these
  expectations, not against V2 or against each other alone.

7. V4 MULTI-THREADING HEAP SAFETY FIX (2026-09-14)
================================================================================
Target: metheorMultiV4

Problem:
In V3, running `metheor tag` with high thread counts (e.g. -t 120) caused:
`malloc_consolidate(): unaligned fastbin chunk detected` and SIGABRT (core dump).
Root cause:
In `run_helper_mt`, `stream_batches` sent `Vec<Record>` batches across 54 worker
threads. In `rust-htslib`, `Record` contains `header: Option<Rc<HeaderView>>`.
`Rc` has a non-atomic reference count (`std::rc::Rc`), violating Send/Sync
thread-safety under concurrency. Additionally, concurrent calls to C HTSlib
memory reallocation (`bam_aux_del` / `bam_aux_append`) across 54 worker threads
corrupted glibc heap metadata (fastbin chunks).

Fix in src/tag.rs:
1. `Record` lifecycle is strictly confined to the main I/O thread.
   `Record` creation, XM modification (`remove_aux` / `push_aux`), BAM writing,
   and deallocation are exclusively performed on the single main thread.
2. Worker threads only receive pure Rust `Vec<ReadPayload>` (no C pointers, no `Rc`,
   Send + Sync) and compute/return `Vec<String>` (XM tag strings).
3. An ordered sliding window pipeline (`stream_tag_records`) coordinates batches:
   dispatching payloads round-robin to workers, while draining and writing
   completed batches in strict original BAM order.
4. Glibc heap corruption is completely eliminated because C BAM structures and
   refcounted headers are never shared across threads.

    cargo test --release --offline -j 2 --bin metheor tag::tests -- --test-threads=1
    cargo build --release --offline
